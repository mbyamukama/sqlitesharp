Phase 1 — File Format Reader

Read-only access to SQLite database files. Opens a .db file, validates the 100-byte header, parses B-tree pages, reads the sqlite_schema table, and walks table rows — all in pure C# with no native interop.

Files Created

  • IO/VfsFile.cs
  • IO/Pager.cs
  • BTree/Cell.cs
  • BTree/MemPage.cs
  • BTree/BTreeCursor.cs
  • BTree/BTree.cs
  • Database.cs
  • SqliteException.cs
  • Terminal/Program.cs

Key Decisions

  • ArrayPool<byte> for page buffers — avoids GC pressure on repeated reads
  • ReadOnlySpan<byte> for zero-copy page access from the pager
  • BinaryPrimitives for big-endian integer reads (matches SQLite's on-disk format)
  • Varint decoder handles all 1–9 byte encodings per the file format spec
  • Interior page navigation via an explicit stack (no recursion)
  • INTEGER PRIMARY KEY correctly shows as NULL in record body (rowid is the key)

Architecture

FileStream (VfsFile) │ ▼ Pager ── reads 100-byte header, serves pages by number │ ▼ MemPage ── parses B-tree page header + cell pointer array │ ▼ BTreeCursor ── navigates interior→leaf pages, reads cells │ ▼ Cell ── varint codec, record header/value parsing │ ▼ Database ── reads sqlite_schema, exposes tables

Phase 2 — Tokenizer + Parser

Full SQL tokenizer and recursive-descent parser producing an abstract syntax tree. Handles keywords, quoted identifiers, string/numeric/blob literals, all comparison and arithmetic operators, and line/block comments. Parser supports SELECT, INSERT, UPDATE, DELETE, CREATE TABLE, and DROP TABLE with expression precedence climbing.

Files Created

  • Compiler/Token.cs
  • Compiler/Tokenizer.cs
  • Compiler/Ast.cs
  • Compiler/Parser.cs
  • Compiler/AstPrinter.cs
  • Tests/TokenizerTests.cs
  • Tests/ParserTests.cs

Key Decisions

  • Recursive-descent parser (not Lemon/LALR) — easier to debug and extend in C#
  • Precedence climbing for binary expressions — correct arithmetic/logical precedence
  • 70+ token types covering all SQLite keywords, operators, and punctuation
  • Supports all identifier quoting styles: "double", `backtick`, [bracket]
  • Line/column tracking on every token for meaningful error messages
  • AST pretty-printer doubles as a test oracle and debugging tool

SQL Supported

  • SELECT with DISTINCT, aliases, *, table.col, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT/OFFSET
  • INSERT INTO … VALUES (single and multi-row)
  • UPDATE … SET … WHERE
  • DELETE FROM … WHERE
  • CREATE TABLE with column types, PRIMARY KEY, AUTOINCREMENT, NOT NULL, UNIQUE, DEFAULT
  • DROP TABLE [IF EXISTS]
  • Expressions: arithmetic, comparisons, IS [NOT] NULL, BETWEEN, IN, LIKE, NOT, AND, OR, function calls, CAST, unary ±

Phase 3 — VDBE + Compiler (SELECT)

Virtual Database Engine with bytecode compilation and execution. Compiles SELECT statements from the parsed AST into a sequence of VDBE opcodes, then executes them against the B-tree layer. Full end-to-end SQL query execution from text to result rows.

Files Created

  • Vdbe/Opcodes.cs
  • Vdbe/VdbeOp.cs
  • Vdbe/Mem.cs
  • Vdbe/Vdbe.cs
  • Compiler/CodeGen.cs
  • Statement.cs
  • Tests/VdbeTests.cs

Key Decisions

  • Register-based VM (like real SQLite) — registers hold typed Mem values
  • Mem class with type tag (Null/Int64/Double/Text/Blob) — clean discriminated union without unsafe code
  • SQLite comparison semantics: NULL sorts first, type affinity ordering (NULL < INT/REAL < TEXT < BLOB)
  • Jump-patching pattern for forward references (WHERE skip, Rewind-to-Close, LIMIT-to-Close)
  • Star expansion: SELECT * emits Column opcodes for all table columns
  • Aggregate detection: separate code path for COUNT/SUM/MIN/MAX with AggStep/AggFinal opcodes
  • Database.Prepare(sql) → Statement → Step() → Row/Done: mirrors the C sqlite3 API

Opcodes Implemented

Control: Halt, Goto, If, IfNot, DecrJumpZero Cursor: OpenRead, Rewind, Next, Column, Rowid, Close Output: ResultRow Literals: Integer, String, Real, Null, Copy Comparison: Eq, Ne, Lt, Le, Gt, Ge Arithmetic: Add, Subtract, Multiply, Divide, Remainder, Concat, Negate Aggregates: AggStep, AggFinal Functions: Function (abs, length, upper, lower, typeof)

Architecture

SQL text │ ▼ Tokenizer Token[] │ ▼ Parser AST (SelectStmt) │ ▼ CodeGen VdbeOp[] program │ ▼ Vdbe.Step() Result rows ←── BTreeCursor reads from Pager

Phase 4 — Write Path (INSERT / UPDATE / DELETE)

Full read-write transaction support with rollback journal, B-tree cell insertion/deletion, page splitting, and VDBE write opcodes. Data written by the C# engine is verified readable by the C sqlite3.exe (v3.54.0) — cross-engine binary compatibility.

Files Created / Modified

  • IO/Pager.cs (rewritten)
  • IO/VfsFile.cs (updated)
  • BTree/Cell.cs (extended)
  • BTree/BTreeWriter.cs (new)
  • Vdbe/Opcodes.cs (extended)
  • Vdbe/Vdbe.cs (extended)
  • Compiler/CodeGen.cs (extended)
  • Database.cs (updated)
  • Tests/WriteTests.cs (new)

Key Decisions

  • Rollback journal — original page content written to -journal file before modification; commit = delete journal; rollback = replay journal
  • Pager state machine: Reader → WriterLocked → WriterCacheMod → WriterFinished (simplified from C's 6-state model)
  • BTreeWriter — separate class from BTreeCursor; handles Insert (find position, insert cell, split if overflow) and Delete (remove cell from pointer array)
  • Page splitting: when a leaf overflows, root converts to interior page with two leaf children
  • Record format: BuildRecord() encodes column values with serial type varints matching the C file format exactly
  • UPDATE = DELETE + INSERT — reads current row, applies SET changes, deletes old row, inserts new row with same rowid
  • Auto-commit: Execute() wraps each statement in Begin/Commit for simplicity

Write Opcodes Added

Transaction: Transaction (begin write txn), AutoCommit Cursor: OpenWrite Record: MakeRecord (serialize values → record blob) Rowid: NewRowid (max + 1) DML: InsertInt, DeleteOp, SeekRowid

Write Path Architecture

INSERT INTO t VALUES (...) │ ▼ Parser → InsertStmt AST │ ▼ CodeGen │ Transaction(write) │ OpenWrite cursor │ NewRowid → reg │ [eval values] → regs │ MakeRecord → blob reg │ InsertInt(cursor, blob, rowid) │ AutoCommit │ ▼ Vdbe executes │ Pager.Begin() → opens journal │ BTreeWriter.Insert(rowid, record) │ → finds leaf page │ → inserts cell (or splits page) │ Pager.Commit() │ → updates page count + change counter │ → syncs journal │ → writes dirty pages to .db file │ → syncs .db file │ → deletes journal (commit point) ▼ Data on disk — readable by C sqlite3.exe ✓

Phase 5 — DDL (CREATE TABLE / DROP TABLE)

Full schema management — create databases from scratch, execute CREATE TABLE (allocates root pages, inserts into sqlite_schema), and DROP TABLE. The C# engine is now fully self-contained: no external tools needed to create or manage databases.

Files Created / Modified

  • DatabaseFactory.cs (new)
  • Vdbe/Opcodes.cs (extended)
  • Vdbe/Vdbe.cs (extended)
  • Compiler/CodeGen.cs (extended)
  • Database.cs (updated)

Key Capabilities

  • DatabaseFactory.CreateNew(path) — creates a valid empty .db file from scratch (magic string, header, empty B-tree page 1)
  • CREATE TABLE — allocates a new root page, initializes it as an empty leaf B-tree, inserts a 5-column record into sqlite_schema
  • DROP TABLE [IF EXISTS] — scans sqlite_schema, deletes matching rows, increments schema cookie
  • IF NOT EXISTS / IF EXISTS — no-op if condition met, error otherwise
  • Schema auto-reload — in-memory schema refreshed after every DDL operation via callback
  • Full self-contained workflow — create DB → CREATE TABLE → INSERT → SELECT → UPDATE → DELETE → DROP TABLE, all in pure C#

DDL Opcodes Added

CreateBtree: Allocate + initialize a new empty leaf page SchemaInsert: Insert row into sqlite_schema SchemaDelete: Delete row from sqlite_schema IncrSchemaCookie: Increment cookie at offset 40 in page 1 ReloadSchema: Trigger in-memory schema refresh

Phase 7 — WAL Mode (Write-Ahead Log)

Write-Ahead Logging implementation — writes go to a WAL file as frames instead of using a rollback journal. Enables faster writes and (conceptually) concurrent readers. Includes checkpoint to transfer WAL frames back to the main database file.

Files Created / Modified

  • IO/Wal.cs (new)
  • IO/Pager.cs (extended)
  • Database.cs (extended)
  • Tests/WalTests.cs (new)

Key Decisions

  • WAL file format: 32-byte header (magic, version, page size, checkpoint seq, salt, checksum) + frames (24-byte header + page data)
  • Frame index: in-memory dictionary mapping page number → WAL offset of latest frame
  • Checksum algorithm: Fibonacci-weighted running checksum over pairs of 32-bit integers (little-endian mode)
  • Read path: WAL checked first → latest committed frame wins over main DB file
  • Write path: dirty pages written as WAL frames; last frame in a transaction marked as commit frame
  • Checkpoint: transfers all committed frames to main DB file, syncs, resets WAL with new salt
  • Auto-detection: WAL file presence on open automatically puts connection in WAL mode

WAL Architecture

┌─────────────────────────────────────────────┐ │ WAL File (.db-wal) │ ├─────────────────────────────────────────────┤ │ Header (32 bytes) │ │ magic │ version │ pageSize │ ckptSeq │ │ salt1 │ salt2 │ checksum1 │ checksum2 │ ├─────────────────────────────────────────────┤ │ Frame 1: [hdr 24B] [page data 4096B] │ │ Frame 2: [hdr 24B] [page data 4096B] │ │ Frame 3: [hdr 24B] [page data 4096B] ←commit│ │ ... │ └─────────────────────────────────────────────┘ Read: page N → check WAL index → if found, read from WAL → else read from main .db file Write: dirty page → WriteFrame(pgno, data, isCommit) commit frame marks transaction boundary Checkpoint: WAL frames → main .db file → reset WAL

Math Functions (30)

Trigonometric: acos, asin, atan, atan2, cos, sin, tan Hyperbolic: acosh, asinh, atanh, cosh, sinh, tanh Logarithmic: exp, ln, log (1 or 2 args), log2, log10 Rounding: ceil/ceiling, floor, trunc Power/Root: pow/power, sqrt Other: abs, degrees, mod, pi, radians, sign

JSON Functions (16)

Scalars (14): json — validate & minify JSON text json_array — build JSON array from args json_array_length — count elements in array json_extract — extract value(s) by path ($.key[0].sub) json_insert — insert without overwrite json_replace — overwrite existing only json_set — insert or overwrite json_remove — delete element(s) at path json_object — build JSON object from key/value pairs json_type — return type name (object/array/integer/real/text/null) json_valid — 1 if valid JSON, 0 otherwise json_quote — wrap SQL value as JSON literal json_patch — RFC 7396 merge patch Aggregates (2): json_group_array — collect values into JSON array json_group_object — collect key/value pairs into JSON object

Key Decisions

  • System.Text.Json (JsonNode API) for JSON manipulation — no external dependencies
  • Null propagation: all functions return NULL when given NULL input (matching SQLite semantics)
  • NaN/Infinity → NULL: math functions return NULL for undefined results (sqrt(-1), log(0))
  • JSON path navigation: supports $, .key, [n] — matching SQLite's path syntax
  • Dispatch pattern: MathFunctions.Execute() and JsonFunctions.Execute() return bool (recognized or not), chained from Vdbe
  • CodeGen bugfix: pre-allocate contiguous result registers before compiling expressions, preventing register overlap when functions allocate argument registers
  • Multi-arg aggregates: CodeGen now compiles all arguments (not just first) for aggregate functions like json_group_object(key, val)

Architecture
